# Test Suite Audit — Coverage Analysis

> **Audience:** Programmers | Mixed
>
> **Thread Context:** N/A (audit/reference)

> **Platform/Backend Scope:** All platforms (tests run headless / NullRHI; many use standalone reimplementations for CI)

## Overview

A coverage analysis of SparkEngine's test suite: how many tests exist, which subsystems they cover, and where gaps remain. The suite has grown substantially since the original audit (April 2026): from 297 test files / 3,647 tests to **485 files / ~5,991 tests** as of 2026-06-08. Most of the original audit's "critical missing test suite" and "medium priority" gaps have since been filled.

## Remaining Coverage Gaps

These categories were the original audit's standing weak spots and remain the most likely places to find untested code:

- **Editor systems (`SparkEditor/Source`, 126 headers):** Historically ~4% tested. The most testable-without-GPU targets remain `UndoRedoManager`, `CommandPalette`, `AssetDatabase`, `PrefabManager`, `SceneSerializer`, `EditorLayoutManager`, `VersionControlSystem`, `LevelStreamingSystem`, and gizmo transform math.
- **Game modules (115 headers across 10 modules):** Per-module mechanic tests are uneven. FPS and MMO have coverage; RPG/ARPG/RTS/Racing/Platformer/OpenWorld/VisualScript modules are lighter.
- **RHI backend implementations** (`D3D11Device`, `D3D12Device`, `VulkanDevice`, `MetalDevice`, `OpenGLDevice`): require hardware; tested implicitly via NullRHI and standalone logic tests.

---

## Acceptably-Untested Categories

These do not need dedicated unit tests:

- **Platform stubs** (`PlatformDirectXMathStubs`, `PlatformD3DStubs`, `PlatformAudioStubs`) — exercised implicitly.
- **Type / enum headers** (`AnimationTypes`, `PhysicsTypes`, `RHITypes`, `GraphicsEnums`) — data-only.
- **Trivial helpers** (`MakeDesc`, `DrawSortKey`, `LogMacros`).
- **Diagnostic debug tools** (`CpuDebugger`, `ThreadDebugger`, `CacheDebugger`, `IODebugger`).

---

## Test Conventions

- Framework: custom `TestFramework.h` with `EXPECT`/`ASSERT` macros (not GoogleTest).
- Naming: `Test<SystemName>.cpp`.
- A large majority of tests use **standalone reimplementations** (no engine/DirectXMath headers) for CI/Linux portability.
- All test files are registered in `Tests/CMakeLists.txt` and run via CTest:

```bash
cd build && ctest --output-on-failure --no-tests=error
```

See also the maintained AUTO: test inventory in `wiki/.../Testing.md`, regenerated by `docs/sync-wiki.sh sync`.
