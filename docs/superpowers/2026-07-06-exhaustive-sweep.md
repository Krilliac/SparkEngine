# SparkEngine Exhaustive Sweep — Prioritized Report

_Whole-codebase audit + deferred-feature design sweep. All findings below survived adversarial verification (the `refutedHigh` set came back empty). Bugs and feature briefs are interleaved into a single recommended sequence at the end._

---

## 1. Executive summary — top 5 to do next

1. **Fix the account-security floor before the W5 onboarding lane lands (game-meta, critical).** `TFAccountSystem.cpp:29` hashes passwords with `std::hash` (non-crypto, GPU-crackable), `TFAccountSystem.cpp:51` never validates password emptiness, and `TFDatabase.cpp:68/219` ignore load/save return values so a corrupt DB silently wipes all accounts on the next write. This is _real onboarding code, not a prototype_, and the onboarding stream (T3–T7) is actively building on top of it — harden it now so the in-flight lane doesn't cement the flaw.
2. **Close the server-authoritative combat cheats (game-combat, 2× critical).** `TFWeaponServer.cpp:72` fires any client-supplied `WeaponId` with no loadout/class check, and `TFWeaponServer.cpp:124` resets the rate-limiter token bucket whenever the weapon id changes — so alternating two weapon ids gives unlimited fire rate. Both are trivially exploitable with a modified client and undermine the entire server-authority model.
3. **Fix the two data-loss bugs in scene serialization (engine-ecs-reflection, high).** Enum fields (`ComponentReflection.cpp:308`) and zero-field mask components (`:928`) are silently dropped on every scene save/load round-trip — a Static wall reloads as a falling Dynamic body, a Mesh collider becomes a Box, trigger/shadow masks reset. This corrupts content invisibly and will erode trust in the editor round-trip that other feature streams depend on.
4. **Repair the editor use-after-free + dirty-tracking gaps (editor, critical/high).** `HierarchyPanel.cpp:1259` (ResetToDefault) frees the SceneFile without clearing `CommandHistory`, so Ctrl+Z after New Scene / Open Project replays commands capturing freed pointers. Compounded by `EditorUI.h:313` never setting `m_sceneModified` on real edits — users lose work with no prompt. `CommandHistory::Clear()` already exists and is simply never called.
5. **Land the onboarding-status lane cleanly, then start the two near-free feature wins.** Verify+commit the uncommitted T2 `TFAccountSystem` (its test may already pass — the `SparkTests.exe` timestamp postdates the source), then proceed T3→T7. In parallel, the **collab-server** and **sp4-dehardcode** streams are both small, unblocked, and high value-to-effort.
