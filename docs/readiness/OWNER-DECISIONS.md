# Release-Readiness Owner Decisions

This file records engineering and product decisions the readiness ledger could
not make on its own. Legal and governance decisions (licensing, trademark,
contribution terms, security contact, support policy, Code of Conduct) are not
here; they stay open in [`docs/governance/GOV-400-DECISIONS.md`](../governance/GOV-400-DECISIONS.md).

A decision here unblocks implementation. It does not close a work item or
promote a capability: closure still needs the item's commands, tests, and
exact-SHA CI evidence (see `statusPromotionRules` in
[`docs/site/readiness.json`](../site/readiness.json)).

| OD-20 | MOD-330 | ARPG dungeon slice budgets: at most 48 simultaneously active monster actors, at most 256 live gameplay entities during combat (hero, monsters, projectiles, loot), 16.67 ms p95 frame time (60 fps) on the certified Windows D3D11 row, and at most 3.0 ms p95 game-thread time for ARPG gameplay systems (AI, combat, skills, loot). | These are target values. | OD-21 | SEC-120 | The 149 deferred parser candidates are classified by evidence, one entry per file, using fixed rules: (1) code that parses bytes from outside the process (files a user or mod can supply, packages, network, save/scene/config files read at runtime) is an inventoried boundary and needs a fuzz target; (2) code that only parses data the engine itself generated in the same process, or build-time/developer tooling that never ships, is exempt with a written justification; (3) generic read/tokenize helpers are helper-exempt, and every parser that calls them is classified on its own. When in doubt, classify as a boundary. | Rules are fail-closed toward fuzzing. | OD-22 | DATA-120 | Krilliac is the accountable owner for encryption at rest and database secrets. stable-v1 policy: no database secret or credential is committed or written to shipped config; secrets come from the environment or the OS credential store. Password material is stored only as salted PBKDF2 hashes, and session tokens are never persisted in plaintext. Encryption at rest for SQLite files relies on host full-disk encryption, documented as the operator's responsibility; no in-database encryption (e.g. SQLCipher) for stable-v1. | This keeps OD-07 (SQLite) without adding a new crypto dependency, and puts the one real requirement (no plaintext secrets or tokens) under test instead of promising database-level encryption. |

## 2026-09-27 owner decisions

| ID | Work item | Decision | Reasoning / consequence |
|---|---|---|---|
| OD-23 | BLD-100 / MOD-390 | **Accommodation removed on 2026-09-28** because the AngelScript build-tree patch (`ThirdParty/Scripting/patches/angelscript-packed-bytecode.patch`) now places stack-resident value objects and return slots at 8-byte addresses: the lane is back to `-fno-sanitize-recover=undefined` with no recoverable check, `Tests/ubsan_suppressions.txt` is deleted, the script-string bindings take their arguments by reference again, and `AngelScriptStackAlignment_*` (`Tests/TestAngelScriptStackAlignmentReal.cpp`) checks every value-object address. Original decision (2026-09-27): the `build-linux-asan` lane makes only UBSan's alignment check recoverable (`-fsanitize-recover=alignment`) and suppresses alignment reports only inside libstdc++'s `bits/basic_string.h` and `bits/basic_string.tcc` (`Tests/ubsan_suppressions.txt`). The native bindings that receive or return script strings (`SPARK_SCRIPT_STRING_ABI` in `AngelScriptEngine.cpp`) are exempt per function and copy each string into an aligned local first. Every other UBSan check still aborts, and `halt_on_error=1` stops on any other alignment report. A real fix, 8-byte-aligned value-type locals in AngelScript's frame layout, stays an open follow-up. | AngelScript keeps value-type script locals on its 4-byte-aligned `asDWORD` stack, so a script `string` can sit at 4 mod 8 and UBSan aborts inside the libstdc++ string members an engine translation unit instantiated. GCC has no per-function ignorelist, and moving those locals to the heap corrupted the stack for functions returning `string` by value, so the VM fix is a frame-layout change deferred past this release. The workflow policy test pinned both the flag and the suppression list; since the removal it asserts that the lane has no recoverable UBSan check and no UBSan suppressions. |
| OD-24 | BLD-100 | Delegated by the owner on 2026-09-28 ("Pick for me"). For the Windows two-tree reproducibility comparison, `tools/compare_build_outputs.py` may normalize exactly one thing: occurrences of the build-root path string inside `.debug$S` (CodeView) sections of COFF members of `.lib` archives, replaced by a fixed placeholder of the same byte length. Every other byte of every artifact (EXE, DLL, PDB-independent image bytes, other sections and other archive members) is compared exactly, and a normalized member whose lengths or section layout differ still fails. The manifest records which members were normalized. | MSVC `/Z7` objects embed the absolute build directory in CodeView records, and the SDK static libraries ship those objects, so two clean builds in different directories cannot match byte-for-byte even when the code is identical. A narrow, recorded normalization keeps the comparison meaningful without weakening it anywhere else; broad masking or skipping `.lib` files would hide real nondeterminism. |
