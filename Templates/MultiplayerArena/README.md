# MultiplayerArena legacy template

MultiplayerArena is a bounded local arena simulation retained for compatibility outside the eight-template editor registry. It demonstrates lobby readiness, symmetric cyan-versus-magenta starts, countdown, scoring, respawn timers, and a deterministic match end without claiming a live network transport or dedicated server.

> **stable-v1 support boundary:** [`stable-v1`](../../docs/site/readiness.json) is blocked and uncertified; its exact host is Windows 11 x64. MultiplayerArena is a legacy, outside-profile local-simulation example and is not stable-v1 release or networking evidence. Its CMake project builds a shared module, not a bundled host/server executable, and no current fixture proves a live packaged match.

The fixed team IDs exposed to host adapters are `1` for cyan and `2` for magenta.

The reflected `Scenes/Arena.sparkscene` uses repository-original authored cyan and magenta duelists, a center-field shield marker, modular walls, corner pylons, and colored spawn lighting. The models were generated by the deterministic Blender pipeline. `Assets/multiplayer_arena_atlas.png` supplies matching character, pickup, arena, network, and UI artwork for a host adapter. Configure the generated project against an installed SparkEngine SDK with CMake 3.25 or newer.

The CMake target produces `MultiplayerArena.dll` on Windows and copies `Assets` beside that module; it does not create a launcher, game host, network transport, or dedicated server. `spark.modules.json` is a module declaration for a separately supplied compatible host. The generic CLI package fixture checks content/launcher assembly with fabricated module and host files and a mocked subprocess, not live process or network behavior.

## Local simulation inputs

When a compatible host supplies an ECS world and input adapter, the module maps cyan to `WASD`/`F` and magenta to `IJKL`/`O`. Its local deterministic rules use a five-second countdown, a first-to-three target, a 90-second limit, a three-unit attack range, and a three-second respawn delay. `R` resets scores, symmetric spawn positions, readiness, and the countdown. No socket, replication, remote-client, or authoritative-server path is exercised here.

## Deterministic rule checkpoints

`Tests/TestTemplatesCompile.cpp` exercises lobby transitions, opposing-team validation, scoring, respawn, overtime, and headless scene ownership. The following describe those local rules and intended host checks; they are not recorded live-play, package-launch, or networking results:

1. Cyan and magenta begin at opposite six-unit spawn points under their matching lights, facing the center marker.
2. Neither player moves during the five-second countdown. After it ends, both stay inside the nine-unit arena clamp.
3. An attack outside three units does nothing; an in-range attack scores once and hides the eliminated duelist for three seconds.
4. First to three ends the match. If the 90-second clock expires tied, the phase enters overtime; otherwise the leader wins. `R` returns to the ready lobby loop.

The wall and corner-pylon meshes are visual composition guides. Movement remains a transport-neutral kinematic sample without collision resolution, so projects should add authoritative physics before using those meshes as blockers.

All source and repository-original artwork are covered by the SparkEngine repository license. No third-party content is bundled.
